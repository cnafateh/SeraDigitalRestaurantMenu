# رابط کاربری، قالب‌ها و پنل مدیریت

## فناوری و مسیرها

رابط با React 19، TypeScript و Vite 8 ساخته شده است. `src/main.tsx` استایل‌های پایه و برنامه را بارگذاری می‌کند. `src/App.tsx` مسیرهای شروع‌شونده با `/admin` را به `AdminPage` و بقیه را به `ExperiencePage` می‌دهد. router کتابخانه‌ای استفاده نشده است؛ `src/hooks/use-route.tsx` با History API (`pushState` و `popstate`) مسیر را نگه می‌دارد و `RouteLink` ناوبری داخلی را بدون reload انجام می‌دهد. لینک‌ها در صورت کلیدهای modifier یا کلیک غیرچپ، رفتار عادی مرورگر را حفظ می‌کنند.

| مسیر صفحه                          | محتوا                                | منبع داده                                        |
| ---------------------------------- | ------------------------------------ | ------------------------------------------------ |
| `/`                                | مجموعهٔ مکان‌های منتشرشده            | `GET /api/venues`                                |
| `/menu/{venueId}`                  | صفحهٔ منو، دسته‌بندی و جست‌وجو       | `GET /api/menu/{venueId}`                        |
| `/dish/{venueId}/{slug}`           | جزئیات آیتم و قیمت variantها         | `GET /api/menu/{venueId}` و یافتن slug در آرایه  |
| `/admin`                           | ورود و پنل ویرایش                    | endpointهای `/api/admin/*`                       |
| `/menu/{venueId}?preview=1`        | پیش‌نمایش خصوصی، شامل مکان منتشرنشده | `GET /api/admin/menu/{venueId}`؛ cookie لازم است |
| `/dish/{venueId}/{slug}?preview=1` | جزئیات آیتم در پیش‌نمایش خصوصی       | همان endpoint ادمین                              |

`?preview=1` صرفاً با وجود پارامتر `preview` فعال می‌شود؛ مقدار آن در کد بررسی نمی‌شود. این پارامتر **راه دور زدن احراز هویت نیست**: API خصوصی بدون نشست `401` می‌دهد. routeهای ناشناختهٔ SPA در وضعیت فعلی ممکن است صفحهٔ مجموعه را نشان دهند؛ صفحهٔ 404 عمومی مستقل پیاده نشده است.

## نمایش عمومی

`ExperiencePage` از مسیر، `venueId` و در صورت وجود `dishSlug` را استخراج می‌کند. در مسیر مجموعه، فهرست مکان‌های منتشرشده را می‌گیرد. در مسیر منو یا آیتم، یک `MenuResponse` می‌گیرد. برای حالت بارگذاری و خطا صفحهٔ جدا دارد. درخواست اثر React با پرچم `active` از به‌روزرسانی state پس از unmount جلوگیری می‌کند.

در منو، دسته‌ها از `category` آیتم‌های همان مکان ساخته می‌شوند. فیلتر دسته و جست‌وجو در **مرورگر** روی دادهٔ دریافت‌شده اجرا می‌شوند؛ جست‌وجو نام، زیرعنوان، توضیح و مواد تشکیل‌دهنده را با حروف کوچک مقایسه می‌کند. API جست‌وجو یا صفحه‌بندی ندارد. کارت هر آیتم کمترین قیمت variantها را با متن `From` نشان می‌دهد. `featured` کلاس ویژهٔ کارت را فعال می‌کند؛ `available=false` برچسب `Sold out` می‌گذارد، ولی کارت همچنان دیده می‌شود.

در صفحهٔ آیتم، کاربر variant را انتخاب می‌کند و قیمت همان گزینه را می‌بیند. مواد، آلرژن‌ها، برچسب‌ها و وضعیت موجودی نمایش داده می‌شوند. انتخاب variant فقط در UI است؛ API سفارش یا ثبت انتخاب وجود ندارد. قیمت با `Intl.NumberFormat("en", {style:"currency", currency: venue.currency})` قالب‌بندی می‌شود، پس زبان نمایش قیمت فعلاً `en` است.

## قالب‌ها و طراحی

کلید `venue.template` به کلاس CSS `theme-${template}` روی صفحهٔ منو و آیتم تبدیل می‌شود. پنج قالب موجود:

| کلید          | مفهوم           | مکان نمونه |
| ------------- | --------------- | ---------- |
| `pizzeria`    | پیتزافروشی      | `forno`    |
| `traditional` | رستوران سنتی    | `narenj`   |
| `fastfood`    | فست‌فود         | `stack`    |
| `cafe`        | کافه            | `morrow`   |
| `gelato`      | بستنی و نوشیدنی | `scoop`    |

پالت پیش‌فرض در `src/platform.css` به پیتزافروشی تعلق دارد و selectorهای چهار قالب دیگر متغیرهای بصری را تغییر می‌دهند. ساختار صفحه و اجزای آن مشترک است؛ قالب فعلی یک layout مستقل یا افزونهٔ قابل بارگذاری نیست. افزودن قالب ششم مستلزم تغییر هم‌زمان نوع TypeScript، فهرست API، اعتبارسنجی بک‌اند، قید SQL، عنوان پنل و CSS است؛ جزئیات در [راهنمای توسعه](development.md) آمده است.

تصاویر hero و آیتم از URLهای ذخیره‌شده در دیتابیس می‌آیند. اگر `item.image` خالی باشد، UI تصویر `venue.heroImage` را جایگزین می‌کند. تصویر hero اولویت دریافت بالا دارد؛ نخستین تصاویر کارت eager و باقی کارت‌ها lazy load می‌شوند. استایل‌ها برای عرض‌های مختلف media query دارند؛ حالت `prefers-reduced-motion: reduce` حرکت‌های تزئینی را حذف می‌کند و کنترل‌ها focus قابل مشاهده دارند. انیمیشن‌های فعلی CSS هستند؛ موتور سه‌بعدی در کد فعلی وجود ندارد.

## پنل مدیریت

پنل در بارگذاری `GET /api/admin/session` را بررسی می‌کند. در نبود نشست، فرم رمز را نشان می‌دهد. پس از ورود، فهرست مکان‌ها (`GET /api/admin/venues`) و منوی مکان انتخاب‌شده (`GET /api/admin/menu/{id}`) بارگذاری می‌شوند. `src/lib/api.ts` همهٔ درخواست‌های frontend را با `credentials: "same-origin"` می‌فرستد و برای متدهای تغییردهنده هدر `X-Sera-Request: dashboard` اضافه می‌کند.

### ویرایش مکان

مدیر می‌تواند مکان جدید بسازد یا نام، شعار، توضیح، مکان، ساعت کاری، کد ارز، تصویر hero، قالب و وضعیت انتشار را تغییر دهد. ID/URL فقط هنگام ایجاد مکان قابل ویرایش است. دکمهٔ «Preview live menu» به URL دارای `?preview=1` می‌رود؛ پیش‌نمایش خصوصی تغییرهای **ذخیره‌شده** را نشان می‌دهد، نه متنِ ذخیره‌نشدهٔ فرم. تغییر قالب با ذخیرهٔ همان رکورد `Venue` انجام می‌شود و منو و آیتم‌ها باقی می‌مانند.

`published=false` مکان را از `/api/venues` و API عمومی منو پنهان می‌کند؛ مدیر همچنان آن را می‌بیند. برای انتشار، checkbox را فعال و مکان را ذخیره کنید. پنل حذف مکان ندارد.

### ویرایش آیتم

پنل برای هر مکان فهرست آیتم‌هایش را نشان می‌دهد و یک dialog برای ایجاد/ویرایش باز می‌کند. فیلدها شامل نام، slug، دسته، زیرعنوان، توضیح، مواد، آلرژن‌ها، tagها، ترتیب، تصویر، variantهای قیمت، `featured` و `available` هستند. هنگام ایجاد، نام به slug لاتین ساده تبدیل می‌شود؛ slug را می‌توان دستی اصلاح کرد. حذف آیتم نیاز به تأیید مرورگر دارد و حذف از دیتابیس فوری است. پنل undo یا سطل بازیافت ندارد.

قیمت‌ها داخل آرایهٔ `variants` ذخیره می‌شوند؛ حداقل یک variant لازم است. افزودن/حذف ردیف اندازه و قیمت در فرم انجام می‌شود، ولی محدودیت حداکثر ۱۰ variant را API اعمال می‌کند. رشته‌های مواد، آلرژن‌ها و tagها در پنل با ویرگول جدا می‌شوند.

### آپلود عکس

`ImageField` هم ورودی URL دستی دارد و هم انتخاب فایل WebP/PNG/JPEG. انتخاب فایل `POST /api/admin/upload` را اجرا و URL پاسخ را در **state فرم** قرار می‌دهد. سپس مدیر باید دکمهٔ ذخیرهٔ مکان یا آیتم را بزند تا این URL در PostgreSQL ثبت شود. حجم مجاز و قواعد دقیق در [قرارداد API](api.md) آمده است. فایل آپلودی حتی اگر فرم در ادامه ذخیره نشود، در volume می‌ماند.

## محدودیت‌های رابط فعلی

- متن رابط فعلاً انگلیسی است و locale/راست‌به‌چپ مستقل پیاده نشده است.
- فیلتر و جست‌وجو سمت مرورگرند؛ برای منوهای بسیار بزرگ به API جست‌وجو و صفحه‌بندی نیاز می‌شود.
- قیمت، تصویر و وضعیت نمایش داده می‌شوند، ولی ثبت سفارش، سبد خرید، پرداخت و موجودی انبار وجود ندارد.
- قالب‌ها پنج کلید ثابت‌اند و پنل فقط بین آن‌ها انتخاب می‌کند؛ سازندهٔ قالب دلخواه در پنل وجود ندارد.
